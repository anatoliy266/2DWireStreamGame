# 5. System — Twitch Integration (Streamer.bot + TypeScript)

## 1. Архитектура
**Twitch Chat** -> **Streamer.bot** -> **WebSocket Server** -> **Game Client (TypeScript)**.

*   **Streamer.bot:** Выступает в роли "драйвера". Он слушает IRC, аутентифицирует пользователей и транслирует события чата через WebSocket.
*   **Game Client (TS):** Подключается к сокету, получает JSON-события, парсит их и выполняет игровую логику.

## 2. Конфигурация Streamer.bot
В Streamer.bot настраивается Action на событие `Twitch Chat Message`.

## 3. Обработка в TypeScript (Input Layer)
Игровой клиент (класс `TwitchInput`) слушает сокет.

### Логика обработки (OnMessage):
1.  **Validation:** Проверяет, начинается ли `message` с разрешенных префиксов (`!`, `sudo`, `ping`, `force`). Если нет — сообщение игнорируется (чат остается чистым от игрового спама).
2.  **User Mapping:**
    *   Проверяет `userId` в базе активных игроков.
    *   Если игрок новый -> Создает `new Node(userId)`.
    *   Если игрок мертв (`Integrity == 0`) -> Игнорирует ввод.
3.  **Parsing:**
    *   Разбивает строку: `const [prefix, action, target] = message.split(' ');`
    *   Проверяет валидность по **Command Protocol**.
4.  **Execution:**
    *   Передает команду в **Game Loop**.
    *   Игра проверяет Latency игрока.
    *   Если `Latency >= 200` (Blackout), команда отклоняется.

## 4. Обратная связь (Feedback)
Игра не пишет в чат (чтобы избежать бана бота за спам). Вся реакция происходит визуально в клиенте (Overlay):
*   **Успех:** Команда вылетает из аватара игрока и попадает в Буфер.
*   **Ошибка (Blackout):** Над аватаром появляется иконка "Замка" или "Перегрева".
*   **Ошибка (Синтаксис):** Сообщение рассыпается на пиксели (эффект "глюка").
