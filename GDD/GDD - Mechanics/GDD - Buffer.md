# Network Buffer — Combo Fusion & Overflow (GDD)
## 1. Назначение системы

Network Buffer — центральный механизм оркестрации команд чата.
при попадании команды в Raw Pool проверяется не подходит ли она для одной из атомарных команд по формуле:

[ MODIFIER? ] + ACTION + [ TARGET? ] + [ DEBUFF? ]


Далее атомарные команды могут сливаться в комбо-команды (Combo Fusion), создавая усиленный эффект атаки или защиты

команды не вошедшие в атомарные команды или незаконченные атомарные команды вызывают переполнение буфера (Overflow), которое наносит урон по ресурсу Latency игрокам.

слоты буфера:
- атакующие 3
- защитные 4

пул заполняется и синтезирует атомарные команды и комбо на всем протяжении хода игроков. 
когда заканчивается ход игроков буфер освобождает слоты атаки атакуя босса
а атака босса тратит защитные слоты

в начале следующего хода на защитные слоты добавляются новые случайные игроки из рейда(можно повторно)


## 2. Термины

Raw Pool — неупорядоченный пул токенов команд из чата.
Unit (Атомарная команда) — базовая собранная команда по грамматике.
Combo Fusion — слияние нескольких Unit в одну комбо-команду.
Overflow (Переполнение буфера) — негативный эффект переполнения буфера, бьющий по Latency игроков.
Latency — ресурс задержки действий игрока (влияет на скорость / надёжность команд).
Execute Buffer — слоты, в которые попадают финальные команды хода.

## 3. Базовая атомарная команда (Unit)

Формат:

Unit = [ MODIFIER? ] + ACTION + [ TARGET? ] + [ DEBUFF? ]


Примеры:

sudo rm core

rm core

heal self

virus node exploit

Характеристики Unit:

type: attack / control / defense

power: базовая сила эффекта

owner: все игроки чьи токены учавствовали в создании команды и комбо-команды

Unit никогда не мутирует в другой тип действия в результате комбо.

## 4. Условия Combo Fusion

Две Unit могут быть слиты в комбо, если выполняется одно из условий:

совпадает ACTION

совпадает TARGET

Примеры:

rm core  + sudo rm core      → можно слить
heal self + heal raid       → можно слить
rm core  + virus node       → нельзя слить


Слияние может продолжаться каскадно (X2 → X3 → X4)

## 5. Результат Combo Fusion

Формула:

U(1) + U(2) → Combo(U)


Свойства Combo:

ACTION не меняется

TARGET не меняется

MODIFIER и DEBUFF объединяются (без появления новых эффектов)

Combo считается как несколько Unit, исполненных одной командой

Комбо-команда визуально и механически является одним объектом в Execute Buffer.

## 6. Усиление эффекта комбо

Комбо усиливает эффект только численно:

FinalEffect = Σ Power(Unit_i) × ComboMultiplier


Где:

Размер комбо	ComboMultiplier
X1	1.0
X2	1.5
X3	2.0
X4	2.6 (кап)

Никаких новых типов урона или специальных эффектов не появляется.


## 7. Переполнение буфера (Overflow)

команды не вошедшие в атомарные команды или незаконченные атомарные команды вызывают переполнение Network Buffer.

OverflowLevel = bufferlength - bufferSafesize
OverflowDamage = OverflowLevel × OverflowPower


OverflowDamage наносится по ресурсу Latency:

владельцам атакующих Unit, вошедших в комбо

игрокам, назначенным на защитные слоты в этом ходу

Опционально при X3+:

часть Overflow может наноситься всему рейду

## 8. Лимиты и защита от эксплойтов

Максимальный размер комбо: X4

Избыточные Unit выше капа:

не сливаются

уходят в Entropy

Повторяющиеся MODIFIER не усиливают эффект, но увеличивают визуальный шум


## 10. Геймдизайнерская цель

Система создаёт:

управляемый хаос

драму риска и награды

мемность («НЕ ДЕЛАЙТЕ Х3, У МЕНЯ ПИНГ 999»)

ощущение живой сети, которая ломается под нагрузкой

Чат не становится умнее —
чат дамажит сам себя.

# 1. Network Buffer — Combo Fusion & Overflow (GDD)

## 1. Назначение системы
Network Buffer — центральный механизм оркестрации команд чата. Это щит и меч рейда.
Система работает циклично:
1.  **Назначение (Target Lock):** В начале хода на 4 защитных слота назначаются конкретные игроки (случайным образом). Они — приоритетные цели Босса.
2.  **Сбор (Raw Pool):** Игроки кидают команды. Любой игрок может отправить команду Атаки (в слот атаки) или Защиты (чтобы закрыть слот защиты и спасти назначенного товарища).
3.  **Синтез:** Команды сливаются в Комбо (Combo Fusion).
4.  **Исполнение:** В конце хода Буфер разряжается.

5.  **Структура Буфера**
*   **Слоты Атаки (3 шт.):** Привязаны к врагам в комнате (A1, A2, A3).
*   **Слоты Защиты (4 шт.):** Привязаны к назначенным игрокам (D1, D2, D3, D4).

## 2. Термины
*   **Designated Node (Назначенный узел)** — игрок, чей никнейм привязан к конкретному защитному слоту в текущем раунде.
*   **Open Slot (Открытый слот)** — защитный слот, который игроки не успели заполнить командой защиты.
*   **Closed Slot (Закрытый слот)** — защитный слот, в котором есть активная команда (Unit или Combo).
*   **Overflow (Переполнение)** — лишние команды, не влезающие в слоты, наносят урон по Latency отправителя.

## 3. Базовая атомарная команда (Unit)
`Unit = [ MODIFIER? ] + ACTION + [ TARGET? ] + [ DEBUFF? ]`

Типы действий ограничены:
*   `ATTACK` — заполняет атакующие слоты.
*   `DEFEND` — заполняет защитные слоты (по порядку или приоритету).

*Лечения (Heal) не существует.*

## 4. Условия Combo Fusion
Две команды сливаются, если совпадают `ACTION` или `TARGET`.
Слияние увеличивает эффективность (Multiplier), но не меняет тип действия.
Макс. комбо: **X4**.

также 2 команды могут слиться в особую команду по некоторым правилам(напиши правила)
количество особых команд ограничено и они являются по сути финишерами(не могут слиться с другими командами ради комбо)

## 5. Протокол Авто-Маршрутизации (Routing)

### А. Атака: «Жадное Комбо»
Любая команда `!attack` направляется в атакующие слоты по принципу концентрации огня:
1.  Система выбирает **Слот A1** и заполняет его до **Combo X4**.
2.  Только после того, как A1 достиг капа (X4), следующие команды `!attack` начинают заполнять **Слот A2**, затем **A3**.
*   **Цель:** Гарантированное уничтожение хотя бы одного врага за ход (Focus Fire).

### Б. Защита: «HP-Приоритет»
Команды `!defend` распределяются динамически для спасения самых уязвимых:
1.  Система анализирует текущую **Integrity (HP)** четырех игроков, назначенных на слоты D1-D4.
2.  Команды направляются в слот игрока с **наименьшим HP**, пока его слот не достигнет **Combo X2** (безопасный минимум).
3.  Затем система переключается на следующего по «слабости» игрока и заполняет его слот до X2.
4.  Когда все назначенные игроки имеют X2, избыточные команды начинают усиливать слоты до **X3 и X4**, начиная снова с самого раненого.
В конце хода проверяются 4 защитных слота:

*   **Слот 1 (Игрок A):** Закрыт (Combo X2).
    *   *Результат:* Урон Босса по Игроку А снижен на (Power × 1.5).
*   **Слот 2 (Игрок B):** Открыт (Пусто).
    *   *Результат:* **Полный урон** от атаки Босса проходит по Игроку B.
*   **Слот 2 (Игрок С):** Закрыт (Combo -X2(босс встроил свою команду в слот, а игроки не перекрыли)).
    *   *Результат:* **повышенный урон** от атаки Босса проходит по Игроку С.

## 6. Спец-команды (Финишеры)
*   **Правило:** Финишеры (например, `!rm -rf`) занимают слот целиком и не участвуют в Fusion.
*   **Приоритет:** Они встают в первый пустой слот своего типа, игнорируя протокол авто-заполнения комбо.

## 7. Переполнение (Overflow)
Если все слоты (3 атаки или 4 защиты) заполнены до X4, а новые команды продолжают поступать:
*   Срабатывает **Overflow**.
*   Все игроки рейда получают **+40 ms Latency**.


## 6. Переполнение (Overflow)
Команды, не вошедшие в слоты и не слившиеся в комбо, вызывают Overflow.
**Наказание:** урон по ресурсу **Latency** всем игрокам в рейде в конце хода игроков.
Это заставляет игроков координироваться ("Слоты полны, не пишите!").


## 10. Геймдизайнерская цель

Система создаёт:
- управляемый хаос
- драму риска и награды
- мемность («НЕ ДЕЛАЙТЕ Х3, У МЕНЯ ПИНГ 999»)
- ощущение живой сети, которая ломается под нагрузкой
- Чат не становится умнее — чат дамажит сам себя.
